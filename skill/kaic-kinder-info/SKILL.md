# kaic-kinder-info — 유치원알리미 조회 도구

교육부 유치원알리미 공시 데이터(14개 항목)를 조회하는 CLI. 파이썬 표준 라이브러리만 쓰므로
별도 설치가 필요 없다.

도구 경로: `{{TOOL_DIR}}`

## 실행 방법

MCP 도구(`kaic-kinder-info`)가 등록돼 있으면 그것을 쓰고, 없으면 CLI를 직접 실행한다.

```
python {{TOOL_DIR}}\kinderinfo.py <명령> ...
```

| 명령 | 용도 | 예시 |
|---|---|---|
| `search <지역>` | 목록 + 핵심 수치 표 | `search "서울 강남구" --age 3` |
| `profile <지역> <이름>` | 1곳 전체 공시 종합 리포트 | `profile "서울 강남구" 강남유정` |
| `profile … --web` | + **원비·시정명령 이력**(웹 공시, 키 불필요) | 원비·행정처분 질문이면 이걸로 |
| `compare <지역> <이름들>` | 비교표 | `compare "서울 강남구" "가나,다라"` |
| `raw <엔드포인트> <지역>` | 원본 JSON | `raw basicInfo2 11680` |
| `schedule <지역> <이름>` | 병설유치원 방학·학사일정 | `schedule "서울 강남구" ○○초등학교병설` |
| `report <지역> <이름들>` | **최종 후보 브리핑**(비교+상세+추이+방문 질문지) | `report "서울 강남구" "가,나" --target --out 브리핑.md` |
| `pick <지역> <이름들>` | 후보 저장 → report/trend/diff 인자 생략 가능 | "이 세 곳이 내 후보야" |
| `trend` | 충원율·원아·근속의 **3년 추이**(5개 차수) | "추세 어때?", "좋아지고 있어?" |
| `diff` | 최신 두 차수 사이 변화만 추림 | 새 공시 직후 "뭐 바뀌었어?" |
| `home <링크>` | 집 좌표 설정(네이버지도 공유 링크) | `home "https://naver.me/XXXX"` |
| `refresh` | 캐시 비우기(새 공시 게시 시) | 조회 결과에 📢 알림이 뜨면 실행 |
| `regions` | 저장된 지역 코드 목록 | |
| `discover <시도>` | 새 시도 코드 탐색(최초 1회) | `discover 경남` |

- 지역: `서울`(시도 전체), `"서울 강남구"`, `강남구`(유일할 때), `11680`(코드, 가장 빠름)
- search 옵션: `--age 3|4|5` `--target` `--estab 공립|사립` `--name <부분명>`
  `--near <km>` `--road`(자차 도로 거리·시간) `--sort name|size|fill|dist` `--limit N`
- 공통: `--fresh`(7일 캐시 무시), `--json`(원자료)
- 출력이 마크다운이므로 그대로 인용하거나 요약해서 답하면 된다.

## 사용자 아이에 맞춰 찾기

`.env`에 `CHILD_BIRTH_YM=YYYY-MM`이 설정돼 있으면 **`--target`을 쓰는 것이 가장 정확하다.**
입학 학년도와 연령반을 자동 계산해(만3세반 = 출생연도 + 4) 해당 연령반만 걸러준다.

설정돼 있지 않은데 사용자가 아이 나이를 말하면, 생년월을 `.env`에 저장해 두자고 제안하거나
`--age N`으로 직접 지정한다. 유치원은 만 3~5세를 받는다.

## 추이를 물으면 (trend / diff)

- **"지금 좋은 곳"과 "좋아지는 곳"은 다르다.** 충원율·근속의 스냅샷만 보지 말고
  `trend`로 방향을 확인한다. 예: 근속 1년 미만 75%→38%는 "교사 대거 교체 후 안정화 중"이라는
  뜻일 수 있다 — 단정하지 말고 방문 질문으로 연결할 것.
- 새 공시(연 2회, 4월말·10월말경) 직후에는 `diff`가 가장 빠르다. 큰 변동이 보이면
  trend 로 흐름을, profile 로 상세를 본다.
- 사용자가 후보를 언급하면 `pick`으로 저장해 두면 좋다. 이후 "내 후보 추이/브리핑"이
  인자 없이 동작한다.

## 후보가 좁혀졌으면 report

사용자가 후보 2~3곳을 정했거나 "정리해줘", "방문 때 뭘 물어보지"라고 하면 `report`를 쓴다.
비교표·상세·**방문 질문지**(공시의 이상 신호를 질문으로 변환)가 한 문서로 나오고
`--out`으로 저장해 배우자와 공유하거나 인쇄해 갈 수 있다. 원비·시정명령·평가와
병설 방학 실측이 기본 포함된다. 처음학교로는 **1~3지망 최대 3곳** 지원이므로
후보가 3곳을 넘으면 줄이는 걸 도와줄 것.

## 결과 해석 가이드

- **충원율**(원아수/인가정원): 높으면 인기, 지나치게 낮으면(30% 미만) 이유를 확인할 만하다.
- **교사 근속**: 공시 구간(1년 미만~6년 이상) 중간값 가중 **추정 평균**이다.
  단정적으로 말하지 말 것. "1년 미만 비율"이 높으면 이직이 잦다는 신호.
- **학급당 원아 수**: 적을수록 여유롭다. 공립 병설이 보통 사립보다 적다.
- **운영시간은 '문 여는 시간'이지 정규 수업 시간이 아니다.** 유치원 정규 교육과정은
  법정 1일 4~5시간이고, 공시된 07~18시 같은 시간대의 나머지는 전부 방과후·돌봄이다.
  병설·사립 공통이므로 운영시간만 보고 비교하면 안 된다.
- **병설유치원은 정규 수업일수가 법정 최소(180일)에 가깝다.** 초등학교 학사일정을 따라
  방학이 길기 때문이다. 사립은 보통 220~240일이라 **50일 가까이 차이 난다.**
  다만 방학 중에도 방과후과정은 운영되어 **'방과후 포함 운영일수'는 양쪽이 비슷하다**(230일 안팎).
  즉 병설은 "다닐 날이 적다"기보다 **"방학 기간을 방과후과정에 의존한다"**가 정확하다.
  그래서 병설을 볼 때는 **방과후 전담교사 인력**(방과후 과정 항목의 전담교사·강사 수)을
  함께 확인해야 한다. 방학 중 담임이 아닌 인력이 아이를 볼 가능성이 크기 때문이다.
- **방학이 언제 며칠인지는 `schedule` 명령으로 본다.** 유치원알리미에 학사일정이 없어
  모(母)초등학교 일정을 NEIS에서 가져온다. 실측하면 방학 합계가 학교마다 67~85일로
  꽤 차이 난다. 단 **초등학교 일정이라 유치원과 정확히 같지 않다는 점을 반드시 함께 말할 것.**
  사립·단설은 NEIS에 없어 조회되지 않으므로 유치원에 직접 문의하도록 안내한다.
  `NEIS_API_KEY`가 `.env`에 없으면 발급처(open.neis.go.kr, 무료)를 안내한다.
- **혼합연령 학급**에도 해당 연령이 포함될 수 있으므로, 연령 필터에 안 걸린 곳도
  후보라면 `profile`로 확인한다.
- 공시는 연 2회(4월말·10월말경) 갱신되며 출력 상단에 `2026년 1차 공시`처럼 기준이 표시된다.
  **원서 접수(처음학교로, 입학 전해 11월) 직전에는 `--fresh`로 최신 자료를 다시 받는다.**
- `⚠ 공시 데이터 점검 중`은 교육부가 해당 항목을 잠근 상태다. 도구 문제가 아니니
  나중에 재시도하라고 안내한다.
- 사용자에게 답할 때는 표를 통째로 붙여넣지 말고 **질문에 맞게 추려서** 설명한다.

## 거리·접근성을 말할 때

- **직선거리는 하한값이다.** 실측하면 우회율(도로÷직선)이 1.0~3.1배까지 벌어진다 —
  직선이 똑같이 541m인 두 곳이 실제로는 720m와 1.20km였다.
  거리를 말할 때는 **`--road` 로 자차 도로 거리·시간을 함께 보고 답할 것.**
  직선거리만 있다면 "직선으로는 가깝다"고만 말한다.
- **우회율 2배 이상(⚠)이면 동선을 의심**한다. 로드뷰 확인을 안내하고, report 를 쓰면
  방문 질문이 자동 생성된다.
- 자차 경로는 OSRM 오픈 데이터 기준이라 **실시간 교통이 반영되지 않는다**(아침 등원 시간대는
  더 걸림). 한국 도로망은 OSM 기반이라 일방통행·골목 최신성이 상용 지도보다 떨어질 수 있다.
  이 한계를 함께 말할 것.
- **집 좌표가 없으면** `home "<네이버지도 공유 링크>"` 로 설정하도록 안내한다.
  카카오맵 링크는 자체 좌표계라 못 쓴다 — 네이버 링크를 달라고 할 것.
- **자차 등하원이라면 진짜 병목은 "유치원 앞에 잠시 정차할 수 있는가"다.** 이 정보는
  어떤 공시·API에도 없다. `profile`이 만들어 주는 **로드뷰 링크를 열어 직접 보라고 안내**한다.
  주소 문자열로 추정하지 말 것 — 대로변 주소여도 아파트 단지 안이면 정차가 쉽고,
  좁은 번길이어도 골목이 막히면 오히려 어렵다.
- **통학차량을 운행하는 유치원이면 거리보다 노선이 중요하다.** 노선은 데이터에 없으므로
  전화로 확인하라고 안내한다.

## 원비·시정명령을 물으면 (`--web`)

- **원비와 행정처분 이력은 Open API에 없고 웹 공시에만 있다.** `profile … --web`으로
  조회한다(키 불필요). 시정명령 이력이 있으면 **가장 앞세워 알릴 것** — 후보 배제급 정보다.
- 원비 해석: 0원 = 과정은 운영하되 학부모 부담 없음, `-` = 해당 연령 과정 없음.
  누리과정 지원 덕에 사립도 월 2만원 안팎인 곳이 많고, 간혹 크게 튀는 곳이 있다.
- `--web` 조회가 실패하면(화면 개편 가능성) 출력에 남는 **원본 링크**로 직접 확인을 안내하고,
  `python kinderweb.py selftest`로 구조 변화를 점검할 수 있다.

## 하지 말 것

- **모집요강·경쟁률·통학구역은 어떤 데이터에도 없다.** 지어내지 말고
  처음학교로(www.go-firstschool.go.kr)나 유치원 전화(출력에 있음)로 안내한다.
- 근속 평균 같은 추정치를 확정된 사실처럼 말하지 않는다.

## 문제 해결

- `인증키가 거부되었습니다` → `.env`의 `KINDER_API_KEY` 확인(따옴표·공백 금지)
- 결과 0곳 → 지역명 확인, `regions`로 저장된 지역 확인, `discover <시도>` 실행
- 경기도는 `discover 경기 --full` 필요(시 안에 구가 있는 구조, 5~10분)
- 그 밖의 증상은 도구 폴더의 `AGENTS.md` 문제 해결 표 참고
